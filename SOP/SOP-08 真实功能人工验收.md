# SOP-08：真实功能人工验收

> ← 返回总览：[[现行开发流程SOP-2026-09-07]]

## 验收前置

- 本次范围涉及 UI（用户界面）或新增交互时，相关方案已明确批准；
- formal（正式开发） 实现和直接相关测试完成；
- 依赖在 `REAL_ACCEPTANCE`（真实功能验收时点） 时点满足，或按批准方案 fail-closed（失败时安全拒绝）；
- 使用可追溯版本的真实前后端、数据库和公开 UI（用户界面）/API（应用程序接口）；
- 自 S5（第五阶段）起，取得阶段总控分配的公共真实验收窗口，并完成下述数据重置与运行就绪检查；
- 验收环境身份达到 `IDENTITY_READY`（验收身份准备就绪）。

## 一套公共环境、真实验收串行

自 S5（第五阶段）起，每阶段默认只运行一套公共真实验收环境，由阶段总控管理。所有模块使用同一固定访问地址，容器编排项目名、主机名、监听端口、前后端、MySQL（关系型数据库）、Redis（缓存服务）、MinIO（对象存储服务）、登录入口与基础身份均应固定且可预测。公共原型网关另行提供界面预览，不进入此队列。

执行 `SINGLE_SHARED_STAGE_ACCEPTANCE_ENVIRONMENT`（阶段单一公共验收环境）与 `REAL_ACCEPTANCE_SERIAL`（真实验收串行）。只有正式实现和直接测试完成、准备请求用户验收的模块才进入队列；同一时刻仅一个模块开展写入型真实验收。开发并行不授予环境占用权，六个开发槽位不代表六套验收环境。

S1（第一阶段）～S4（第四阶段）已经完成的历史环境事实按当时规则保留，不按新规则重建或改写。

## 精确部署与切换数据

进入窗口时部署本模块精确的 formal task commit/tree（正式任务提交及目录树），并同时记录阶段固定基点和 Flyway（数据库迁移工具）最高版本；不能只登记无法定位的“最新代码”。

公共容器和地址可以复用，数据不能无条件沿用。切换模块前，按实际情况采用一种最小安全重置：

1. 重建干净数据库；
2. 重建独立 schema（数据库模式）；
3. 恢复阶段基线数据快照；
4. 清理并重新初始化明确的数据命名空间。

重置后迁移版本必须满足本次正式任务目录树。可以在公共数据库服务内建立临时数据库或模式，但不能默认为每个模块长期保留完整独立服务栈。

## 基础身份与最小运行就绪检查

验收身份可通过幂等 bootstrap（引导初始化） 准备 tenant（租户）/company（公司）/org（组织）、专用 user（用户）/employee（员工）、最小 role（角色） 和 data scope（数据范围），但不得预造主数据、业务配置、单据、余额、流水或其他业务 provider（能力提供方）；业务事实必须通过正式 UI（用户界面）/API（应用程序接口） 产生。

凭据不得进入 Git（分布式版本控制系统）、Flyway（数据库迁移工具）、日志、回执或任务消息。登录链每套环境只做一次 smoke（冒烟检查）；多身份切换应先建立下一身份有效 Session（服务端会话），再退出上一身份。验收账号默认不强制改密；批量前置配置可使用正式接口辅助工具，不得直写业务表、伪造能力提供方或替代用户真实功能验收。

邀请用户前，逐项确认后端健康、前端可打开、正式登录成功、公共门户和工作区可进入、目标菜单存在、正式路由可打开、运行代码与声明的正式任务提交及目录树一致，以及数据库迁移版本正确。此处是最小运行就绪检查，不新增重型门禁、证据子提交或重复全仓测试。

## 验收结论与窗口交接

模块任务直接请求用户验收真实功能。用户通过前不得分层合并或声明 `VERIFIED`（已经验证状态）。用户通过后，模块任务向阶段总控报告：

- 获批 UI（用户界面） commit/tree（提交/目录树）；
- formal（正式开发） commit/tree（提交/目录树） 和 clean（干净无未提交变更） 状态；
- 直接相关测试；
- 真实验收场景与结论；
- 依赖关闭/保留状态；
- 当前公共验收窗口占用及待释放状态、其他共享资源释放情况；
- 可合并分支链。

随后由阶段总控执行以下固定顺序：

```
用户真实功能验收通过
→ task → feat → group → stage    （任务分支依次合入功能分支、分组分支和阶段分支）
→ 释放公共验收窗口
→ 下一模块取得窗口
```

用户通过但尚未完成分层合并时，不提前释放公共验收窗口。模块结束后停止其专属开发资源，公共环境继续供后续模块使用；阶段收口时统一停止并保留。

## 独立环境的临时例外

只有用户明确批准并发真实验收，或存在候选迁移无法安全重置、外部依赖或版本互斥、会话身份或数据无法可靠隔离、公共环境无法解决的已确认技术阻断时，由阶段总控向用户报告后才可临时创建独立环境。

获批并发时，例外环境须隔离容器编排项目名、主机名、监听端口、数据库、数据卷、数据命名空间和必要浏览器会话。仅更换 `127.0.0.1`（本机回环网络地址）的端口不能隔离 Cookie（浏览器会话凭据）。

模块直接相关自动化测试和必要 Testcontainers（临时容器集成测试工具）测试仍使用各自所需隔离，不因公共真实验收串行而被一律串行化；实际争用同一重型资源时由总控安排窗口。
