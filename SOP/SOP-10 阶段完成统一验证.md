# SOP-10：阶段完成统一验证

> ← 返回总览：[[现行开发流程SOP-2026-09-07]]

## 累计阶段统一验证

模块开发期不重复跑全仓；阶段结束时，由阶段总控在唯一累计 clean（干净无未提交变更） Stage（阶段） tree（版本控制目录树） 上集中执行一轮联动和整体验证。自 S5（第五阶段）起，所有模块累计后只重建一次公共真实验收环境，从干净数据库执行 Flyway（数据库迁移工具）全部正式迁移，并构建、启动同一累计阶段的前后端：

1. 快照和控制文件轻量检查。
2. 根 Maven（面向爪哇编程语言的构建工具）完整测试。
3. 前端全量测试、typecheck（类型检查）和 production build（生产构建）。
4. Compose（容器编排） 及真实运行配置。
5. 全新 MySQL（关系型数据库）空库上的 Flyway（数据库迁移工具）V1（第一版迁移）至当前累计最高版本迁移、历史记录及校验。
6. 契约、权限、租户/company（公司）、审计、幂等和并发验证。
7. business-link plan（业务联动规划） 登记的累计联动场景。
8. 上一阶段 provider（能力提供方） 的真实消费和 fail-closed（失败时安全拒绝） 场景。
9. 唯一事实 writer（写入者）、引用保护和共享资源顺序。
10. 下一阶段 provider（能力提供方） 目录。

在同一固定地址完成阶段全量功能与跨模块业务链验收，不逐个恢复历史模块独立环境。“集中一轮”不表示失败后禁止复验，也不自动要求每次失败都把所有无关模块从头重跑。失败时定位精确原因，由责任模块按已批准边界最小修复并正向累计，再按下述适用裁定复验；不恢复旧双轴审查、重复 review（审查）或第二套正式门禁。

## 验证并行与共享资源顺序

同一累计目录树上，互不写共享事实的后端测试、前端测试与构建、轻量治理检查、分支祖先关系及能力目录核对，可按实际资源条件并行。全新数据库迁移、容器编排启动和停止、共用数据库或会话的业务链、库存与资金唯一写入者相关共享资源验证必须串行安排。测试内部的临时隔离数据库不得接入或修改公共真实验收业务数据。

## 测试夹具批量诊断与原负责人修复

2026-09-01 人工裁定针对 S4（第四阶段）最终收尾引入诊断性批量盘点；S5（第五阶段）～S7（第七阶段）出现同类问题时可按裁定范围沿用，并须在执行前把适用授权同步到仓库控制登记与阶段计划。它不是每个阶段都必须额外运行的一轮测试。

- 只适用于已证明为旧测试数据、固定日期、陈旧数量断言、换行符、测试事务边界或累计能力接入导致的单测试文件夹具漂移。生产实现、正式迁移、接口及运行环境须无对应故障；不得削弱权限、隔离、幂等、原子性或失败拒绝断言。
- 已授权的当前修复完成并累计后，可从最新干净阶段基线运行一次诊断性 `mvn -fae test`（构建工具在可继续模块中收集测试失败）。此命令仅生成失败清单，不是阶段通过证据，也不放宽前端、治理、容器编排或真实业务链的失败策略。
- 总控批量登记技术续作，明确原可见任务、唯一允许测试文件、执行阶段、分组、角色和正式分支；仍由原唯一负责人修复。不同模块的只读定位和单文件修改可并行，重型共享测试资源由总控或运行副手串行调度。
- 每项修复须保留原失败可复现的 RED（失败复现）证据、原失败方法及完整测试类或最小受影响回归的 GREEN（通过）结果，并通过 `git diff --check`（版本控制差异格式检查），确认精确改动仅为获批测试文件且工作树干净，再分层累计。
- 此类零生产改动修复不需要界面原型、界面批准或重复真实业务验收。涉及生产代码、编译、数据库迁移、正式接口、界面、安全、数据完整性或无法证明仅为夹具的问题时，立即停止该批量方式并报告精确阻断，另按具体授权处置。
- 诊断临时 Testcontainers（临时容器集成测试工具）资源使用独立数据库、随机端口、独立容器及匿名卷，生命周期结束由测试框架停止和移除；不把它们混同为需长期保留的正式验收材料。

## 最终验证恢复边界与历史裁定

9 月 1 日批量盘点裁定原要求“诊断后完成全部已批准修复，再从最新干净阶段完整认证一次”，最终认证恢复首次精确失败即停；最终认证如又遇新的夹具问题，须再次取得明确授权，不能无限循环自行修复。

随后 S4（第四阶段）阶段计划记录了更具体的用户授权：BM-007（电脑打印设置模块）从后端失败点恢复，BM-002（公司设置模块）及 BM-029（收蛋记录模块）从前端失败点恢复，不重跑当时已经完成且未受影响的验证。这些是相应任务、版本和时间点的执行裁定，不是任何阶段都可以跳过完整认证的通用许可。

因此执行时须同时核对原批量裁定、当前阶段最新计划及后续明确授权，采用实际适用的恢复边界；未受影响旧结论可以按授权保留，新增改动与未关闭失败必须验证，诊断失败清单、过时目录树或不相关旧报告都不能替代当前结果。第五阶段增量复验另按 [[SOP-07 直接相关测试]] 执行，不复活整套重复审查。

## 测试基础设施提速：已记录，尚未证明落地

2026-09-01 已记录 MySQL（关系型数据库）Testcontainers（临时容器集成测试工具）与 Spring Context Cache（应用上下文缓存）复用提速裁定。当前核对到人工裁定输入，未在本次绑定的控制登记和变更记录中找到对应提速专项落地证据；不把它写成已完成优化或当前开发前置。

后续实施须先登记测试基础设施技术任务和唯一负责人，从最耗时测试套件的小范围试点开始。建议方向为同一测试进程内复用容器和应用上下文、减少重复迁移，并证明用例之间数据隔离；不得跨测试运行借用旧容器状态冒充全新数据库。必须保留真实数据库语义、阶段全新空库完整迁移、原测试集合和关键断言，并提供优化前后容器启动、迁移次数、上下文创建与总耗时对照。不得借提速修改生产业务或中断正在运行的最终阶段验证。

公共真实验收环境复用已是现行规则，测试基础设施复用是否完成是另一项事实，两者不能相互替代。

## 现行轻量治理命令

以下为开发执行入口示例，不表示本次文档更新已运行这些业务治理检查：

```
python scripts/p0_contracts.py verify-snapshot docs/p0/contracts/P0.4-R4    # （使用蟒蛇编程语言验证第一期第四版修订四契约快照）
python scripts/p0_governance.py validate-control p0-control.yml --snapshot docs/p0/contracts/P0.4-R4    # （使用蟒蛇编程语言按快照验证项目控制文件）
python scripts/p0_governance.py check-stage-business-link-plan <plan> --control p0-control.yml    # （使用蟒蛇编程语言检查阶段业务联动规划）
python -m unittest scripts.tests.test_p0_contracts scripts.tests.test_current_development_flow    # （使用蟒蛇编程语言运行契约与现行开发流程单元测试）
```

具体 Maven（面向爪哇编程语言的构建工具）、前端、Compose（容器编排）、Flyway/MySQL（数据库迁移工具/数据库） 和业务链命令由当前累计 Stage（阶段） 的实际工程配置确定，不引用退役脚本。
