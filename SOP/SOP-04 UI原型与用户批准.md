# SOP-04：UI（用户界面） 原型与用户批准

> ← 返回总览：[[现行开发流程SOP-2026-09-07]]

## 适用条件

存在可交互 UI（用户界面） 或新增交互决策时，必须先制作原型。纯后端/技术续作不得为满足形式而虚构 UI（用户界面）；是否为零 UI（用户界面） 必须由任务范围或用户裁定明确。

## 原型要求

- 分支：`prototype/p0/s{stage}/{scope}`（第一期阶段交互原型分支模板）。
- 使用真实前端技术栈、完整公共 PortalShell/workspace（门户外壳/工作区）和仅用于原型的 Mock（模拟数据）。
- 顶栏、导航、标签页、身份区、菜单加载和正式路由承载结构直接复用累计阶段公共实现；模块只实现业务内容区，不复制、裁剪或重制私有门户壳，不伪造登录身份或用免登录页面绕过公共壳层。
- 必须可在本地浏览器运行。
- V2/V3（第二版/第三版） 在同一 prototype（交互原型） 分支迭代。
- 模块任务自行构建、更新、打开稳定预览地址，并在自己的可见任务中直接向用户请求 UI（用户界面） 人工验收。
- 用户明确批准后记录获批 prototype（交互原型） commit/tree（提交/目录树）。

prototype（交互原型） 只用于 UI（用户界面） 决策，禁止 merge（合并） 或 cherry-pick（摘取提交） 到 formal（正式开发） task（任务分支）、Feat（功能分支）、Group（分组） 或 Stage（阶段）。formal（正式开发） ancestry（祖先链） 必须从最新 clean（干净无未提交变更） Stage（阶段） 重新建立。

## 已退役 UX（用户体验） 概念

当前不存在全局 UX（用户体验） baseline（基线）、参考页注册表或 `UXChangeRequest`（用户体验变更申请） 机器门禁。页面布局、样式和复用方式由用户在该模块原型验收中直接裁决。缺少旧 baseline（基线）/reference（引用） 回执不得阻塞已经获得用户 UI（用户界面） 批准的正式开发。

完整复用公共门户是现有公共代码的承载要求，不恢复全局 UX（用户体验）基线、参考页注册表或额外机器回执。模块业务内容的交互方案仍由用户在该模块原型中直接裁决。

## 原型并行与模块独立批准

- `UI_PROTOTYPE_REVIEW_PARALLEL`（原型评审并行）：多个模块可同时展示、接收反馈、迭代和请求批准，一个模块等待用户意见不得阻塞其他模块。
- `MODULE_UI_APPROVAL_INDEPENDENT`（模块界面批准独立生效）：本模块获批后，按 `FORMAL_DEVELOPMENT_AFTER_MODULE_UI_APPROVAL`（模块界面获批后开始正式开发）进入正式准备与实现，不等待其他模块裁决；仍须满足本模块的准备结果、依赖和共享资源条件。
- `FORMAL_DEVELOPMENT_PARALLEL`（正式开发并行）：遵守 [[SOP-02 任务调度与唯一Owner]] 的并发上限及每模块唯一负责人。
- 自 S5（第五阶段）起执行 `STAGE_PROTOTYPE_GATEWAY_MULTI_ROUTE`（阶段单一原型网关多路预览）：一个轻量网关、一个对外监听端口，为每个模块提供独立稳定主机名或路由，并隔离构建产物和页面状态。一个模块更新产物不得覆盖另一个模块；不得为原型默认创建多套完整前端、后端和数据库服务栈。
- `PROTOTYPE_PREVIEW_DOES_NOT_OCCUPY_REAL_ACCEPTANCE_WINDOW`（原型预览不占用真实验收窗口）：原型示例数据和轻量交互只支持界面决策，不是生产能力提供方，也不构成真实功能验收结果。
- S5（第五阶段）当前计划登记原型网关对外端口为 `13500`（第五阶段原型预览端口），真实验收前端端口为 `13600`（第五阶段公共真实验收端口）；后续阶段以各自计划登记为准，不把这两个数值固定为全项目规则。
