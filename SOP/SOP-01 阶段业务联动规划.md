# SOP-01：阶段业务联动规划

> ← 返回总览：[[现行开发流程SOP-2026-09-07]]

## 触发时点

阶段总控必须在以下任一时点，以届时最新 clean（干净无未提交变更） `stage/sN`（阶段编号占位符对应的阶段分支模板） 为基线完成或更新 `STAGE_BUSINESS_LINK_PLAN`（阶段业务联动规划）：

- 当前阶段首个正式 task（任务分支） 创建前；
- 已在开发中的阶段开始下一滚动批次前；
- 开发中出现新的实质依赖事实时。

规划不循环复审，不追溯推翻已验收模块，不一次性规划或实现 S1（第一阶段）～S7（第七阶段） 全部模块。

## 固定产物

- 人工可读：`docs/p0/stages/s{stage}/business-link-plan.md`（阶段业务联动规划人工可读文件路径）
- 机器可读：`docs/p0/stages/s{stage}/business-link-plan.json`（阶段业务联动规划机器文件路径）
- Schema（结构约束）：`docs/governance/schema/stage-business-link-plan.schema.json`（阶段业务联动规划结构约束文件路径）
- 轻量检查：`check-stage-business-link-plan`（阶段业务联动规划轻量检查命令）

## 必须梳理的内容

1. 上一阶段已经存在、可公开消费的 provider（能力提供方）。
2. 当前阶段已批准 BM/TI（业务模块/技术项）、业务流程、事实源和业务链。
3. provider（能力提供方）、consumer（能力消费方）、查询依赖和写入依赖。
4. 删除/停用等反向引用保护。
5. 唯一事实 writer（写入者）。
6. Flyway（数据库迁移工具）、Portal（门户）、router（路由器）、权限码、错误码等共享资源窗口。
7. 无环开发波次和模块负责人。
8. 阶段结束需要执行的真实联动场景。
9. 留给下一阶段的 provider（能力提供方） 目录。

## 现行依赖类型

| 类型 | 说明 | 调度规则 |
| --- | --- | --- |
| `HARD_RUNTIME`（运行时硬依赖） | 真实运行必须依赖 provider（能力提供方） | provider（能力提供方） 不得晚于 consumer（能力消费方）；未关闭时只暂停受影响能力 |
| `HARD_ACCEPTANCE`（验收时硬依赖） | 可先实现独占部分，但完整验收必须接通 provider（能力提供方） | 只在相关功能申请真实验收前阻断 |
| `OPTIONAL_FAIL_CLOSED`（可选能力安全拒绝） | 当前可延期、可空或安全拒绝 | 不阻断无关功能，必须保留明确提示和后续接线点 |
| `REFERENCE_PROTECTION`（反向引用保护） | 删除/停用前查询下游引用 | 不得反向制造核心 provider（能力提供方） 的普遍开发前置 |
| `SHARED_FACT_WRITER`（共享事实唯一写入者） | 多模块消费同一事实 | 只允许一个公开 writer（写入者），其余模块调用公开服务 |
| `SHARED_RESOURCE_SERIAL`（共享资源串行占用） | Flyway（数据库迁移工具）、Portal（门户）、router（路由器） 等共享资源 | 阶段总控安排单一窗口，不等同业务硬依赖 |

Mock（模拟数据）、seed（种子数据）、测试夹具、硬编码、空实现和跨域直表均不能充当生产 provider（能力提供方）。

## 缺失依赖处置

缺失 provider（能力提供方） 只能选择：

1. `REUSE_EXISTING_PROVIDER`（复用现有能力提供方）：复用现有公开能力。
2. `MINIMAL_PUBLIC_SEAM`（最小公开接缝）：增加最小公开 seam/adapter（接缝/适配器），不增加新业务功能。
3. `OPTIONAL_FAIL_CLOSED`（可选能力安全拒绝）：安全拒绝或字段可空，登记后续接线点。
4. `OUT_OF_CURRENT_SCOPE`（移出当前范围）：移出当前范围并登记未来 owner（负责人）。

依赖发现不得自动新增 BM/TI（业务模块/技术项）、交互或业务功能，不得提前拉入未来阶段模块。任何范围扩大必须重新取得用户明确批准。

S5（第五阶段）2026-09-05 的执行补充：公共依赖只补解除当前阻断的最小公开能力；某个读取接口或公共路由已合入阶段，不等于消费者接线和整项依赖都已关闭。依赖状态须精确到已交付部分、未接通部分及阻断动作；列表、详情、草稿等不依赖缺失能力的功能可继续开发，不把局部硬阻断扩大到整个模块。延期能力保留在计划中，不因延期被自动删除或扩成当前必做。

## 强链路局部模式

S4（第四阶段） 库存、S5（第五阶段） 交易、S6（第六阶段） 结算默认可以只对受影响业务链启用纵向链优先：

```
上一阶段公开 provider    （上一阶段公开能力提供方）
→ 当前阶段核心写入
→ 当前阶段查询/引用保护
→ 当前阶段真实联动验证
```

其他阶段只有出现真实强依赖且经用户或阶段总控裁定时才启用。未受影响模块继续按波次并行，不得因一个模块 BLOCKED（已阻塞） 而停止整个阶段。
