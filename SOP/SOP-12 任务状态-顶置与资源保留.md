# SOP-12：任务状态、顶置与资源保留

> ← 返回总览：[[现行开发流程SOP-2026-09-07]]

模块任务标题格式：

```
S{stage} BM-{id} {模块名}（{当前周期}）    （阶段编号、业务模块编号、模块名和当前周期组成的任务标题模板）
```

周期至少使用：

- `Prototype PREPARE`（原型只读预读准备）
- `UI 原型开发中`（用户界面原型开发中）
- `等待 UI 验收`（等待用户界面验收）
- `正式 PREPARE`（正式开发只读预读准备）
- `正式开发中`（正式业务开发中）
- `轻量测试中`（直接相关轻量测试中）
- `等待真实验收`（等待用户真实功能验收）
- `验收通过待合并`（真实功能验收通过并等待分层合并）
- `已验收并合入 Stage`（已经验收并合入阶段分支）
- `精确 BLOCKED：{最小原因}`（精确阻塞：最小原因）

未彻底完成的模块任务保持普通可见、不顶置。只有同时满足以下条件才标记“（已验收并合入 Stage（阶段））”并顶置：

1. 用户真实功能验收通过；
2. 已按 task（任务分支）→feat（功能分支）→group（分组）→stage（阶段） 合入累计 Stage（阶段）；
3. 模块专属开发资源已经停止；自 S5（第五阶段）起，模块公共真实验收窗口已经释放，阶段共享环境继续运行；
4. 最终 commit（提交）、tree（版本控制目录树） 和工作树 clean（干净无未提交变更） 已核对。

S1（第一阶段）～S4（第四阶段）的历史验收资源按当时规则处理。阶段共享验收环境在阶段收口时统一停止并保留，不因单个模块结束而停止。相关分支、工作树、提交和验收材料继续保留；归档、删除或物理清理须取得用户批准。[[SOP-10 阶段完成统一验证]] 的测试框架自主管理的临时诊断资源按其明确生命周期处理。
