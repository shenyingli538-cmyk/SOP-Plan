# Apifox

## 一句话定位
**API 设计、开发、测试、文档一体化** 的协作平台，常被称为"API 界的 Postman + Swagger + JMeter + 文档"全家桶（国产工具）。

## 它做什么（核心能力）
- **接口文档与设计**：以 OpenAPI/Swagger 规范设计 API，自动生成接口文档，支持 Mock 数据。
- **接口调试**：像 Postman 一样直接发送请求调试接口（GET/POST 等），支持环境变量、各类鉴权。
- **自动化测试**：接口自动化测试、断言、批量/流程测试、定时任务，可做回归测试；性能测试也支持。
- **数据 Mock**：自动生成模拟数据，前端可先基于 Mock 开发，不必等后端接口。
- **团队协作**：接口文档共享、多人协作、评论、权限管理；与 Git、Jenkins、CI 集成。
- **代码生成**：根据接口定义生成各语言的客户端调用代码、测试代码。

## 工作流价值
- 一个工具收敛"设计文档 + 调试 + 测试 + Mock"，替代 Postman / Swagger / JMeter 等分散工具，减少切换。
- 前后端可并行：前端用 Mock 先跑，后端同步实现，接口以文档为契约。
- 适合团队接口统一管理和自动化测试，国内中文文档与支持友好。

## 成本与风险
- **学习成本**：中低，有 Postman/Swagger 基础很快上手。
- **付费**：有免费版，团队/企业版按席位与功能订阅；部分高级测试能力需付费。
- **数据与生态**：接口数据存其云端（自托管可按需），需评估数据与团队习惯；相比 Postman 国际化生态小一些。
- **定位偏接口/测试**：如果团队完全没做接口测试的工作流，就用不上。

## 建议
- 是**软件开发团队做 API 设计 / 联调 / 自动化测试**、希望一个工具替代 Postman + Swagger + JMeter → 非常值得加入，尤其适合前后端分离与接口协作密集的项目。
- **没有接口开发/测试需求（纯内容、非技术）** → 用不上，无需考虑。
